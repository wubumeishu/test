# H5 防缓存配置完整方案

## 📅 配置时间
2026-04-29

## 🎯 目标

彻底解决 H5 端的页面缓存问题，确保用户始终能获取最新版本的资源。

---

## 一、问题背景

### 浏览器缓存机制

浏览器为了提升性能，会缓存以下资源：
1. **HTML 文件**：入口页面
2. **JavaScript 文件**：应用逻辑
3. **CSS 文件**：样式文件
4. **图片/字体**：静态资源

### 缓存带来的问题

1. **用户看不到更新**：即使部署了新版本，用户仍然使用缓存的旧版本
2. **功能异常**：新旧代码混用导致功能错误
3. **用户投诉增加**："为什么我看不到新功能？"
4. **运维成本高**：需要指导用户手动清除缓存

---

## 二、解决方案

### 方案概述

采用**多层防护**策略，从 HTML 到静态资源全面防止缓存：

```
┌─────────────────────────────────────┐
│  第一层：HTML 防缓存                │
│  meta 标签强制不缓存 HTML           │
└─────────────────────────────────────┘
              ↓
┌─────────────────────────────────────┐
│  第二层：静态资源 Hash              │
│  文件名带 hash，内容变化则名称变化  │
└─────────────────────────────────────┘
              ↓
┌─────────────────────────────────────┐
│  第三层：版本检测                   │
│  自动检测版本，提示用户刷新         │
└─────────────────────────────────────┘
```

## 三、配置详解

### 配置 1：HTML 防缓存（index.html）

#### 文件位置
```
my-bazi-app/index.html
```

#### 添加的 meta 标签

```html
<!-- 防止页面缓存 -->
<meta http-equiv="Cache-Control" content="no-cache, no-store, must-revalidate">
<meta http-equiv="Pragma" content="no-cache">
<meta http-equiv="Expires" content="0">
```

#### 完整示例

```html
<!DOCTYPE html>
<html>
  <head>
    <meta charset="UTF-8" />
    
    <!-- 防止页面缓存 -->
    <meta http-equiv="Cache-Control" content="no-cache, no-store, must-revalidate">
    <meta http-equiv="Pragma" content="no-cache">
    <meta http-equiv="Expires" content="0">
    
    <script>
      var coverSupport = 'CSS' in window && typeof CSS.supports === 'function' && (CSS.supports('top: env(a)') ||
        CSS.supports('top: constant(a)'))
      document.write(
        '<meta name="viewport" content="width=device-width, user-scalable=no, initial-scale=1.0, maximum-scale=1.0, minimum-scale=1.0' +
        (coverSupport ? ', viewport-fit=cover' : '') + '" />')
    </script>
    <title></title>
    <!--preload-links-->
    <!--app-context-->
  </head>
  <body>
    <div id="app"><!--app-html--></div>
    <script type="module" src="/src/main.ts"></script>
  </body>
</html>
```

#### 各标签说明

| 标签 | 作用 | 兼容性 |
|------|------|--------|
| `Cache-Control: no-cache, no-store, must-revalidate` | HTTP/1.1 标准，强制不缓存 | 现代浏览器 |
| `Pragma: no-cache` | HTTP/1.0 标准，兼容旧浏览器 | 所有浏览器 |
| `Expires: 0` | 设置过期时间为 0，立即过期 | 所有浏览器 |

#### 工作原理

```
用户访问页面
  ↓
浏览器读取 meta 标签
  ↓
发现 Cache-Control: no-cache
  ↓
不使用缓存，向服务器请求最新 HTML
  ↓
获取最新的 HTML 文件
  ↓
HTML 中引用的 JS/CSS 文件名带 hash
  ↓
如果 hash 变化，浏览器请求新文件
  ↓
加载最新版本
```

### 配置 2：静态资源 Hash（vite.config.ts）

#### 文件位置
```
my-bazi-app/vite.config.ts
```

#### 配置内容

```typescript
import { defineConfig } from "vite";
import uni from "@dcloudio/vite-plugin-uni";

export default defineConfig({
  plugins: [uni()],
  server: {
    proxy: {
      '/api': {
        target: 'http://127.0.0.1:9000',
        changeOrigin: true,
      }
    }
  },
  build: {
    // 确保打包文件名带有 hash，便于版本更新时强制刷新
    rollupOptions: {
      output: {
        // JS 入口文件名（带 hash）
        entryFileNames: 'assets/[name]-[hash].js',
        // JS chunk 文件名（带 hash）
        chunkFileNames: 'assets/[name]-[hash].js',
        // 静态资源文件名（带 hash）
        assetFileNames: 'assets/[name]-[hash].[ext]'
      }
    },
    // 生成 source map 便于调试（生产环境建议设为 false）
    sourcemap: false,
    // chunk 大小警告限制（单位：KB）
    chunkSizeWarningLimit: 1000,
    // 清空输出目录
    emptyOutDir: true
  }
});
```

#### Hash 占位符说明

| 占位符 | 说明 | 示例 |
|--------|------|------|
| `[name]` | 文件名 | `index` |
| `[hash]` | 内容 hash | `a1b2c3d4` |
| `[ext]` | 文件扩展名 | `js`, `css`, `png` |

#### 打包后的文件结构

```
dist/
├── assets/
│   ├── index-a1b2c3d4.js          # JS 入口文件
│   ├── vendor-e5f6g7h8.js         # 第三方库
│   ├── chunk-i9j0k1l2.js          # 代码分割块
│   ├── index-m3n4o5p6.css         # CSS 文件
│   ├── logo-q7r8s9t0.png          # 图片文件
│   └── font-u1v2w3x4.woff2        # 字体文件
├── index.html
└── version.json
```

#### Hash 的作用

1. **内容变化 → Hash 变化 → 文件名变化**
   ```
   修改前：index-a1b2c3d4.js
   修改后：index-e5f6g7h8.js
   ```

2. **文件名变化 → 浏览器认为是新文件 → 重新下载**
   ```html
   <!-- 旧版本 -->
   <script src="/assets/index-a1b2c3d4.js"></script>
   
   <!-- 新版本 -->
   <script src="/assets/index-e5f6g7h8.js"></script>
   ```

3. **未修改的文件 → Hash 不变 → 继续使用缓存**
   ```
   vendor-e5f6g7h8.js  # 第三方库未变，hash 不变，继续缓存
   ```

## 六、服务器配置（推荐）

### Nginx 配置

为了进一步加强防缓存，建议在服务器端也配置：

```nginx
server {
    listen 80;
    server_name your-domain.com;
    root /var/www/html;
    index index.html;

    # HTML 文件不缓存
    location ~* \.html$ {
        add_header Cache-Control "no-cache, no-store, must-revalidate";
        add_header Pragma "no-cache";
        add_header Expires "0";
    }

    # version.json 不缓存
    location = /version.json {
        add_header Cache-Control "no-cache, no-store, must-revalidate";
        add_header Pragma "no-cache";
        add_header Expires "0";
    }

    # 带 hash 的静态资源长期缓存
    location ~* \.(js|css|png|jpg|jpeg|gif|svg|woff|woff2|ttf|eot)$ {
        # 只有文件名包含 hash 才长期缓存
        if ($request_filename ~* "-[a-f0-9]{8,}\.(js|css|png|jpg|jpeg|gif|svg|woff|woff2|ttf|eot)$") {
            add_header Cache-Control "public, max-age=31536000, immutable";
        }
    }

    # SPA 路由支持
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

### Apache 配置

```apache
<IfModule mod_headers.c>
    # HTML 文件不缓存
    <FilesMatch "\.(html)$">
        Header set Cache-Control "no-cache, no-store, must-revalidate"
        Header set Pragma "no-cache"
        Header set Expires "0"
    </FilesMatch>

    # version.json 不缓存
    <Files "version.json">
        Header set Cache-Control "no-cache, no-store, must-revalidate"
        Header set Pragma "no-cache"
        Header set Expires "0"
    </Files>

    # 带 hash 的静态资源长期缓存
    <FilesMatch "\-[a-f0-9]{8,}\.(js|css|png|jpg|jpeg|gif|svg|woff|woff2|ttf|eot)$">
        Header set Cache-Control "public, max-age=31536000, immutable"
    </FilesMatch>
</IfModule>
```

## 八、常见问题

### Q1：为什么还是看到旧版本？

**可能原因**：
1. 浏览器强缓存（Service Worker）
2. CDN 缓存
3. 代理服务器缓存

**解决方法**：
1. 清除浏览器缓存（Ctrl+Shift+Delete）
2. 清除 Service Worker（Application → Service Workers → Unregister）
3. 清除 CDN 缓存
4. 使用隐私模式测试

### Q2：文件名没有 hash？

**可能原因**：
1. Vite 配置错误
2. 打包命令错误

**解决方法**：
1. 检查 `vite.config.ts` 配置
2. 确认使用 `npm run build:h5` 打包
3. 删除 `dist` 目录后重新打包

### Q3：版本检测不生效？

**可能原因**：
1. `version.json` 被缓存
2. `version.json` 不存在
3. 不是 H5 平台

**解决方法**：
1. 确认 `version.json` 可访问
2. 确认服务器配置了不缓存 `version.json`
3. 确认在 H5 平台测试
