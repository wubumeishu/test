# H5 版本检测与强制更新机制

## 功能概述

针对 H5 端实现了自动版本检测与强制更新机制，确保用户始终使用最新版本的应用。

## 实现原理

### 1. 版本文件

**位置**: `my-bazi-app/public/version.json`

**内容**:
```json
{
  "version": "1.0.0"
}
```

**说明**:
- 版本号格式：`x.y.z`（语义化版本号）
- 每次发布新版本时，手动更新此文件中的版本号
- 文件位于 `public` 目录，会被直接复制到打包输出目录

### 2. 检测时机

**触发时机**: 每次页面显示时（`onShow` 生命周期）

**优点**:
- ✅ 用户切换标签页回来时会检测
- ✅ 用户从后台切换回前台时会检测
- ✅ 页面首次加载时会检测
- ✅ 不会错过任何更新

**平台限制**: 仅在 H5 平台生效（使用 `// #ifdef H5` 条件编译）

### 3. 检测逻辑

```typescript
async function checkUpdate() {
  try {
    // 1. 加上时间戳防止请求到缓存的 version.json
    const timestamp = new Date().getTime();
    const response = await fetch(`/version.json?t=${timestamp}`);
    const data = await response.json();
    const serverVersion = data.version;
    
    // 2. 获取本地存储的版本号
    const localVersion = uni.getStorageSync('APP_VERSION');

    // 3. 比较版本号
    if (localVersion && localVersion !== serverVersion) {
      // 发现新版本，更新本地版本号
      uni.setStorageSync('APP_VERSION', serverVersion);
      
      // 强制重载页面清除缓存
      uni.showModal({
        title: '发现新版本',
        content: '系统已升级，请点击确定刷新页面加载最新内容。',
        showCancel: false,
        success: () => {
          window.location.reload(true); // true 表示硬刷新
        }
      });
    } else if (!localVersion) {
      // 首次访问，记录版本号
      uni.setStorageSync('APP_VERSION', serverVersion);
    }
  } catch (error) {
    console.error('检查版本更新失败:', error);
  }
}
```

### 4. 版本比较策略

**简单字符串比较**:
- 直接比较版本号字符串是否相等
- 只要版本号不同就提示更新
- 适用于严格的版本控制

**优点**:
- 实现简单
- 逻辑清晰
- 不会遗漏任何版本变化

## 使用方法

### 发布新版本

1. **修改版本号**

   编辑 `my-bazi-app/public/version.json`：
   ```json
   {
     "version": "1.0.1"
   }
   ```

2. **打包前端**

   ```bash
   cd my-bazi-app
   npm run build:h5
   ```

3. **部署到服务器**

   将 `dist/build/h5` 目录下的所有文件部署到服务器

4. **用户访问**

   - 用户访问应用时，会自动检测到新版本
   - 弹出提示框：「发现新版本」
   - 用户点击「确定」后，页面强制刷新
   - 加载最新的代码和资源

### 版本号规范

**语义化版本号**: `主版本号.次版本号.修订号`

- **主版本号** (Major): 重大功能变更或不兼容的 API 修改
  - 例如：`1.0.0` → `2.0.0`
  
- **次版本号** (Minor): 新增功能，向下兼容
  - 例如：`1.0.0` → `1.1.0`
  
- **修订号** (Patch): 问题修复，向下兼容
  - 例如：`1.0.0` → `1.0.1`

**示例**:
```
1.0.0 - 初始版本
1.0.1 - 修复排盘 bug
1.1.0 - 新增档案管理功能
2.0.0 - 重构整个应用架构
```

## 技术细节

### 防缓存策略

**问题**: 浏览器可能缓存 `version.json` 文件，导致无法获取最新版本号

**解决方案**: 请求时添加时间戳参数
```typescript
const timestamp = new Date().getTime();
const response = await fetch(`/version.json?t=${timestamp}`);
```

**效果**:
- 每次请求的 URL 都不同
- 浏览器不会使用缓存
- 始终获取最新的版本号

### 硬刷新机制

**普通刷新** (`window.location.reload()`):
- 可能使用浏览器缓存
- 不一定加载最新资源

**硬刷新** (`window.location.reload(true)`):
- 强制从服务器重新加载
- 清除所有缓存
- 确保加载最新资源

### 本地存储

**存储位置**: `localStorage`（通过 `uni.getStorageSync`）

**存储内容**:
```javascript
{
  "APP_VERSION": "1.0.0"
}
```

**作用**:
- 记录用户当前使用的版本号
- 用于与服务器版本号比较
- 持久化存储，刷新页面不丢失

```typescript
// #endif
```

**其他平台**:

- App：使用热更新或应用商店更新

- 建立版本基线，为后续检测做准备

## 常见问题

### Q1: 为什么每次切换页面都会检测？

**A**: 为了确保用户始终使用最新版本。

**场景**:
- 用户打开应用后，开发者发布了新版本
- 用户切换到其他标签页，再切换回来
- 此时会检测到新版本，提示更新

### Q2: 会不会频繁弹窗？

**A**: 不会。

**原因**:
- 只有当服务器版本号与本地版本号不同时才弹窗
- 用户刷新后，本地版本号会更新
- 下次检测时版本号相同，不会再弹窗

### Q3: 如何测试版本检测功能？

**A**: 按照以下步骤测试：

1. **清除本地存储**
   ```javascript
   // 在浏览器控制台执行
   uni.removeStorageSync('APP_VERSION')
   ```

2. **刷新页面**
   - 首次访问，不会弹窗
   - 本地存储记录版本号 `1.0.0`

3. **修改版本号**
   - 编辑 `public/version.json`
   - 改为 `1.0.1`

4. **重新打包部署**
   ```bash
   npm run build:h5
   ```

5. **刷新页面**
   - 检测到版本不同
   - 弹出更新提示

### Q4: 开发环境会影响吗？

**A**: 不会影响开发。

**原因**:
- 开发环境使用 `npm run dev:h5`
- Vite 会自动热更新
- 不需要手动刷新页面
- 版本检测不会干扰开发流程

### Q5: 如何禁用版本检测？

**A**: 注释掉 `App.vue` 中的检测代码：

```typescript
onShow(() => {
  console.log("App Show");
  forceHideNativeTabBar();
  
  // 临时禁用版本检测
  // #ifdef H5
  // checkUpdate();
  // #endif
});
```
