# 前端跨域问题修复

## 📅 修复时间
2026-04-29 20:02

## ❌ 问题描述

前端在 H5 模式下调用后端 API 时出现 `request:fail` 错误：

```
19:54:32.401 📤 [useBaziStore] 请求参数: {name: "1", gender: 1, ...}
19:54:34.423 网络请求错误: {errMsg: "request:fail"}
19:54:34.428 ❌ [useBaziStore] 排盘失败: {errMsg: "request:fail"}
```

## 🔍 问题原因

1. **跨域问题**：前端运行在 `http://localhost:5173`，后端运行在 `http://127.0.0.1:9000`
2. **缺少代理配置**：vite.config.ts 中没有配置开发服务器代理
3. **直接请求跨域 URL**：浏览器阻止了跨域请求

## ✅ 解决方案

### 1. 添加 Vite 代理配置

**文件**：`my-bazi-app/vite.config.ts`

```typescript
import { defineConfig } from "vite";
import uni from "@dcloudio/vite-plugin-uni";

export default defineConfig({
  plugins: [uni()],
  server: {
    proxy: {
      '/api': {
        target: 'http://127.0.0.1:9000',
        changeOrigin: true,
        // 不需要 rewrite，因为后端路由就是 /api 开头
      }
    }
  }
});
```

**说明**：
- 所有以 `/api` 开头的请求会被代理到 `http://127.0.0.1:9000`
- `changeOrigin: true` 修改请求头的 origin，避免后端拒绝请求

### 2. 修改请求工具配置

**文件**：`my-bazi-app/src/utils/request.ts`

```typescript
// 从环境变量读取 API 基础地址
// 开发环境使用空字符串（通过 vite 代理）
// 生产环境使用完整 URL
const baseURL = import.meta.env.DEV 
  ? '' 
  : (import.meta.env.VITE_API_BASE_URL || 'http://127.0.0.1:9000')
```

**说明**：
- **开发环境**（`import.meta.env.DEV === true`）：使用空字符串，请求会走 vite 代理
  - 例如：`/api/fortune/calculate` → vite 代理 → `http://127.0.0.1:9000/api/fortune/calculate`
- **生产环境**：使用完整 URL，直接请求后端服务器

## 📝 请求流程

### 开发环境（H5 模式）

```
前端页面 (localhost:5173)
    ↓
发起请求: /api/fortune/calculate
    ↓
Vite 代理拦截
    ↓
转发到: http://127.0.0.1:9000/api/fortune/calculate
    ↓
后端处理并返回
    ↓
Vite 代理返回给前端
    ↓
前端接收响应
```

### 生产环境（小程序/App）

```
前端应用
    ↓
发起请求: http://your-domain.com/api/fortune/calculate
    ↓
直接请求后端服务器
    ↓
后端处理并返回
    ↓
前端接收响应
```

## 🔧 调试技巧

### 1. 查看网络请求

打开浏览器开发者工具（F12）→ Network 标签：
- 查看请求 URL：应该是 `/api/fortune/calculate`（相对路径）
- 查看请求状态：应该是 200
- 查看响应数据：应该包含排盘结果

### 2. 查看控制台日志

应该看到：
```

🎯 [useBaziStore] 排盘结果: {...}
```

### 3. 后端日志


## ⚠️ 注意事项

1. **小程序环境**：小程序不支持代理，必须配置合法域名
2. **生产环境**：需要在服务器上配置 CORS 或使用 Nginx 反向代理
3. **环境变量**：确保 `.env.development` 文件存在且配置正确
