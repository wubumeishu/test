# 前后端联调测试指南

## 测试环境准备

### 1. 启动后端服务

```bash
cd bazi-admin
uvicorn main:app --host 127.0.0.1 --port 9000 --reload
```

**验证**:
- 访问: http://127.0.0.1:9000/docs
- 应该能看到 Swagger UI 文档
- 确认 `/api/archives/sync` 接口存在

### 2. 启动前端服务

```bash
cd my-bazi-app
npm run dev:h5
```

**验证**:
- 访问: http://localhost:5173
- 应该能看到前端页面

### 3. 检查环境变量

确认 `my-bazi-app/.env.development` 配置正确:

```env
VITE_API_BASE_URL=http://127.0.0.1:9000
```

## 测试场景

### 场景 1: 首次启动 (本地无数据)

**步骤**:
1. 清空本地存储:
   ```javascript
   // 在浏览器控制台执行
   uni.removeStorageSync('bazi_archives')
   uni.removeStorageSync('bazi_current_id')
   ```

2. 刷新页面

**预期结果**:
- 控制台输出: `📂 档案数据加载成功: 0 条`
- 控制台输出: `🔄 检测到用户已登录，开始云端同步...`
- 控制台输出: `📤 本地档案数量: 0`
- 控制台输出: `✅ 云端同步成功`
- 控制台输出: `📥 云端档案数量: X`

### 场景 2: 本地有数据，云端无数据

**步骤**:
1. 在前端添加一个档案:
   ```javascript
   const archiveStore = useArchiveStore()
   archiveStore.addArchive({
     name: '张三',
     gender: 1,
     birthDate: '1990-05-15',
     birthTime: '14:30',
     relation: '本人',
     isDefault: true
   })
   ```

2. 刷新页面

**预期结果**:
- 本地档案上传到云端
- 控制台输出: `🔄 实际同步数量: 1`
- 云端返回包含该档案的列表

### 场景 3: 本地有数据，云端也有数据

**步骤**:
1. 使用 Swagger UI 直接在云端创建一个档案:
   ```json
   {
     "archives": [
       {
         "archive_id": "cloud-001",
         "name": "李四",
         "gender": 0,
         "calendar_type": "solar",
         "birth_year": 1992,
         "birth_month": 8,
         "birth_day": 20,
         "birth_hour": 10,
         "birth_minute": 0,
         "tags": "朋友",
         "is_default": false,
         "local_created_at": 1714233600000
       }
     ]
   }
   ```

2. 在前端刷新页面

**预期结果**:
- 本地档案和云端档案合并
- 根据 `local_created_at` 时间戳决定保留哪个版本
- 最终显示云端的最新数据

### 场景 4: 手动触发同步

**步骤**:
1. 在组件中添加同步按钮:
   ```vue
   <button @click="archiveStore.syncWithCloud()">
     同步到云端
   </button>
   ```

2. 点击按钮

**预期结果**:
- 显示 Toast: "云端同步成功"
- 控制台输出同步日志
- 档案列表更新

### 场景 5: 网络失败处理

**步骤**:
1. 关闭后端服务
2. 在前端触发同步

**预期结果**:
- 显示 Toast: "同步失败，使用本地数据"
- 控制台输出: `❌ 云端同步失败`
- 本地数据不受影响
- 用户可以继续使用本地功能

### 场景 6: 归宗算法测试

**步骤**:
1. 在本地创建档案 A (时间戳: 1000)
2. 同步到云端
3. 在云端修改档案 A (时间戳: 2000)
4. 在本地修改档案 A (时间戳: 1500)
5. 再次同步

**预期结果**:
- 云端的版本 (时间戳 2000) 被保留
- 本地的版本 (时间戳 1500) 被覆盖
- 最终显示云端的最新数据

## 调试技巧

### 1. 查看网络请求

**浏览器开发者工具 → Network**:
- 找到 `/api/archives/sync` 请求
- 查看 Request Payload (发送的数据)
- 查看 Response (返回的数据)

### 2. 查看控制台日志

**关键日志**:
```
📂 档案数据加载成功: X 条
🔄 检测到用户已登录，开始云端同步...
📤 本地档案数量: X
✅ 云端同步成功: 同步成功，共处理 X 个档案，实际同步 X 个
📥 云端档案数量: X
🔄 实际同步数量: X
💾 档案列表已保存
```

### 3. 查看本地存储

**浏览器开发者工具 → Application → Storage**:
- `bazi_archives`: 档案列表
- `bazi_current_id`: 当前选中的档案 ID

### 4. 查看后端日志

**后端控制台**:
```
INFO:     127.0.0.1:xxxxx - "POST /api/archives/sync HTTP/1.1" 200 OK
```

## 常见问题

### Q1: 同步后数据丢失

**原因**: 云端数据覆盖了本地数据

**解决**:
- 检查时间戳是否正确
- 确认归宗算法逻辑
- 查看后端返回的数据

### Q2: 无法同步

**原因**: 网络请求失败或后端服务未启动

**解决**:
1. 检查后端服务是否运行
2. 检查 CORS 配置
3. 查看浏览器控制台错误信息
4. 查看 Network 面板

### Q3: 重复同步

**原因**: `isSyncing` 标志未正确设置

**解决**:
- 检查 `finally` 块是否执行
- 确认 `isSyncing.value = false` 被调用

### Q4: 数据格式错误

**原因**: 本地格式和云端格式转换错误

**解决**:
- 检查 `convertToCloudArchive` 函数
- 检查 `convertToLocalArchive` 函数
- 查看后端返回的数据格式
