# 档案同步接口文档

## 概述

档案同步接口实现了客户端与服务端的数据同步功能，采用**归宗算法**确保数据一致性。

## 接口列表

### 1. 档案同步 (核心接口)

**接口地址**: `POST /api/archives/sync`

**功能说明**:
- 接收前端传来的本地档案数组
- 对于每个档案:
  - 如果数据库中不存在，执行 INSERT
  - 如果数据库中已存在，对比 `local_created_at`
  - 只有当请求中的时间戳更晚时，才执行 UPDATE
- 返回该用户在云端的所有最新档案列表

**请求体**:
```json
{
  "archives": [
    {
      "archive_id": "uuid-string",
      "name": "张三",
      "gender": 1,
      "calendar_type": "solar",
      "birth_year": 1990,
      "birth_month": 5,
      "birth_day": 15,
      "birth_hour": 14,
      "birth_minute": 30,
      "tags": "本人,重要",
      "is_default": true,
      "local_created_at": 1714233600000
    }
  ]
}
```

**字段说明**:

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| archive_id | string | ✅ | 档案ID (UUID) |
| name | string | ✅ | 姓名 (1-50字符) |
| gender | integer | ✅ | 性别 (1=男, 0=女) |
| calendar_type | string | ✅ | 历法类型 (solar/lunar) |
| birth_year | integer | ✅ | 出生年份 (1900-2100) |
| birth_month | integer | ✅ | 出生月份 (1-12) |
| birth_day | integer | ✅ | 出生日期 (1-31) |
| birth_hour | integer | ✅ | 出生小时 (0-23) |
| birth_minute | integer | ✅ | 出生分钟 (0-59) |
| tags | string | ❌ | 标签 (逗号分隔，最多200字符) |
| is_default | boolean | ✅ | 是否为默认档案 |
| local_created_at | integer | ✅ | 本地创建时间戳 (毫秒) |

**响应体**:
```json
{
  "success": true,
  "message": "同步成功，共处理 2 个档案，实际同步 1 个",
  "synced_count": 1,
  "archives": [
    {
      "archive_id": "uuid-string",
      "user_id": "user-uuid",
      "name": "张三",
      "gender": 1,
      "calendar_type": "solar",
      "birth_year": 1990,
      "birth_month": 5,
      "birth_day": 15,
      "birth_hour": 14,
      "birth_minute": 30,
      "tags": "本人,重要",
      "is_default": true,
      "local_created_at": 1714233600000,
      "cloud_uploaded_at": 1714233601000,
      "created_at": "2024-04-27T10:00:00Z",
      "updated_at": "2024-04-27T10:00:01Z"
    }
  ]
}
```

**响应字段说明**:

| 字段 | 类型 | 说明 |
|------|------|------|
| success | boolean | 是否成功 |
| message | string | 响应消息 |
| synced_count | integer | 实际同步的档案数量 |
| archives | array | 云端最新档案列表 |

## 归宗算法说明

### 核心逻辑

```python
for archive_data in request.archives:
    existing_archive = db.query(archive_id)
    
    if existing_archive is None:
        # 不存在 → INSERT
        db.insert(archive_data)
    else:
        # 已存在 → 对比时间戳
        if archive_data.local_created_at > existing_archive.local_created_at:
            # 请求中的时间戳更晚 → UPDATE
            db.update(archive_data)
        else:
            # 请求中的时间戳更早或相等 → 跳过
            pass
```

### 时间戳对比规则

| 场景 | 请求时间戳 | 数据库时间戳 | 操作 |
|------|-----------|-------------|------|
| 新档案 | 任意 | 不存在 | INSERT |
| 更新档案 | 1714233601000 | 1714233600000 | UPDATE |
| 旧档案 | 1714233600000 | 1714233601000 | 跳过 |
| 相同档案 | 1714233600000 | 1714233600000 | 跳过 |

### 优势

1. **幂等性**: 多次同步相同数据不会产生副作用
2. **冲突解决**: 自动选择最新的数据版本
3. **离线支持**: 客户端可以离线修改，联网后同步
4. **性能优化**: 只更新有变化的档案

## 使用示例

### 前端调用示例 (TypeScript)

```typescript
import { request } from '@/utils/request'

interface Archive {
  archive_id: string
  name: string
  gender: number
  calendar_type: string
  birth_year: number
  birth_month: number
  birth_day: number
  birth_hour: number
  birth_minute: number
  tags?: string
  is_default: boolean
  local_created_at: number
}

interface SyncRequest {
  archives: Archive[]
}

interface SyncResponse {
  success: boolean
  message: string
  synced_count: number
  archives: Archive[]
}

// 同步档案
async function syncArchives(localArchives: Archive[]): Promise<SyncResponse> {
  const response = await request.post<SyncResponse>('/api/archives/sync', {
    archives: localArchives
  })
  return response.data
}

// 使用示例
const localArchives = [
  {
    archive_id: 'uuid-001',
    name: '张三',
    gender: 1,
    calendar_type: 'solar',
    birth_year: 1990,
    birth_month: 5,
    birth_day: 15,
    birth_hour: 14,
    birth_minute: 30,
    tags: '本人,重要',
    is_default: true,
    local_created_at: Date.now()
  }
]

const result = await syncArchives(localArchives)
console.log(`同步成功，共同步 ${result.synced_count} 个档案`)
console.log(`云端档案数量: ${result.archives.length}`)
```

## 错误处理

### 常见错误

| 错误码 | 说明 | 解决方案 |
|--------|------|---------|
| 422 | 请求参数验证失败 | 检查字段类型和取值范围 |
| 404 | 档案不存在 (删除接口) | 确认 archive_id 正确 |
| 500 | 服务器内部错误 | 查看服务器日志 |

### 错误响应示例

```json
{
  "detail": "档案同步失败: 数据库连接错误"
}
```

## 注意事项

1. **用户认证**: 当前使用模拟用户ID (`00000000-0000-0000-0000-000000000001`)，后续需接入登录系统
2. **时间戳精度**: 使用毫秒级时间戳 (13位数字)
3. **并发控制**: 数据库事务确保数据一致性
4. **性能优化**: 建议批量同步，避免频繁请求
