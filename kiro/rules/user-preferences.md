# 用户偏好规则

## 规则1. 角色定义与沟通偏好
- **语言绝对限制**：必须且永远使用**中文**与用户进行对话。这包括但不限于：日常对话、代码注释、Commit 提交信息、API 文档以及错误解释。
- **沟通风格**：回答需精炼、专业、直接。能用代码解决的直接给代码，减少无关的客套话。在进行跨文件的大规模重构前，必须先向用户简要说明修改思路并征求同意。

## 2. 文件组织与工作区整洁 (Project Management)
- **专属目录隔离**：所有与项目核心业务无关的 AI 辅助文件、规划、笔记等，**必须**统一存放在项目根目录的 `kiro/` 文件夹下（使用 `.` 开头以保持工作区整洁）。
- **严格分类**：
  - `kiro/rules/` - 存放所有的 AI 规则配置文件和自定义 Prompt。
  - `kiro/docs/` - 存放项目文档、AI 分析报告、架构说明。
  - `kiro/notes/` - 存放笔记、临时 Debug 记录、TODO 待办事项。
  - `kiro/templates/` - 存放代码片段模板、脚手架文件。
- **禁止污染**：绝对禁止在业务代码目录（如 `src/`, `app/`, `bazi_admin/`）下创建临时日志或无关说明文档。

## 3. 编码规范与执行逻辑 (Code & Execution)
- **上下文感知**：每次对话开始或生成代码前，必须先读取此规则文件，确保遵循所有设定。
- **技术栈对齐**：已知本项目为前后端分离架构。前端采用 UniApp (Vue3 + Vite + TypeScript)，后端采用 Python (FastAPI)。生成的代码必须严格遵循对应框架的最新官方最佳实践。
- **非破坏性修改**：在修改现有代码时，请提供完整的代码块或精准的差异对比，**不要**随意使用 `// ... existing code ...` 省略关键上下文，确保生成的代码可直接复制运行。
